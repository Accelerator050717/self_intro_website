# 角色分层素材说明

本轮于 2026-09-22 将原正面人物制作成五张可独立绑定的二维图层。人物仍来自用户提供的同一个冰蓝发、黑色卫衣、公仔比例角色。没有生成另一个人物，没有上传照片，也没有使用图像生成服务或新增模型下载。

## 来源与公开边界

- 唯一处理输入为现有公开衍生图 `public/images/avatar/front-960.webp`，画布 720 × 960，透明背景。处理前实际查看了它和私有正面原图。
- 输入 SHA-256：`e58894d907d73cfe682f43e90df5b0bea490ea3e1717ec26a94b58db650ce4b8`。本轮没有覆盖此图，也没有覆盖四张原图。
- `assets/originals/` 中的原始参考图、`.venv-assets/` 环境和 `.verification/` 内部原型继续留在忽略目录。本轮运行必需的五张优化图层和坐标清单位于 `public/images/avatar/rig/`，无需私有原图即可在新 clone 中运行网站。

## 实际处理方法

可复现脚本：`scripts/process-avatar-rig.py`。它使用本地 Pillow、NumPy 与 SciPy，在现有正面透明图上进行手工标定的遮罩和纹理补足。所有遮罩按四倍分辨率绘制，再用 Lanczos 缩回，避免二值裁切的硬锯齿。

1. 沿脸下缘、头发末端和卫衣 V 形领口分出头部及可见颈部。脸、眼睛和头发没有重绘，也没有添加眨眼色块。
2. 沿画面右侧袖子的内缘分出挥手手臂，并将原袖子、袖口和原手从 body 底图移除。另一侧手臂、裤子与鞋留在 body 图层。
3. 将挥手侧分成上臂、前臂及原手，做重叠的圆弧关节遮罩。肩端使用相邻原衣袖像素做短距离边缘延伸；没有拉长整条衣袖。
4. 领口背后用原卫衣内领纹理提供有限遮挡；腋下保留最小原布料补片，避免放下手时出现透明缝。右腰原袖底的细小尖角已从躯干轮廓中收掉。
5. 手的近端做小范围原皮肤纹理延伸，并安排在前臂袖口下面。这样独立转动手腕时袖口仍遮住接缝。手保留原图自然微握造型，没有虚构张开的五指。
6. 清除肢体遮罩外的孤立 alpha 碎点和所有完全透明像素的无用 RGB，再输出 WebP quality 95、透明 alpha。编码有正常的有损 RGB 压缩，不能将最终 WebP 称为与输入逐像素相同。

运行方式（已有本地素材环境）：

```powershell
.\.venv-assets\Scripts\python.exe scripts/process-avatar-rig.py
```

独立复现仅需 Python 和 `Pillow==12.3.0`、`numpy==2.5.3`、`scipy==1.18.1`；不需要 rembg 或原抠图模型。脚本从已提交的正面衍生图生成运行图层，并在 `.verification/avatar-rig/` 生成自包含的 `prototype.html`、静态叠层图和数值检查结果。打开这个仅供本地验证的 HTML，可以点击 Greeting 或拖动时间轴检查动作。它不是站点路由，也不会加入正式导航。

## 文件与骨架接口

五张图均保留完整 720 × 960 透明画布，以原始像素坐标对齐，不做各自裁边。运行图层合计 **99,516 字节**，另有约 4 KB 的 `rig.json`，其中记录文件大小、SHA-256、alpha 范围和时间线。

| 图层 | 文件 | 字节 | 内容 |
| --- | --- | ---: | --- |
| body | `body.webp` | 35,268 | 躯干、非挥手侧手臂、裤子、鞋及最小关节背衬 |
| upper-arm | `upper-arm.webp` | 5,096 | 画面右侧上臂及肩端重叠区 |
| forearm | `forearm.webp` | 4,604 | 原前臂袖子、袖口及肘端重叠区 |
| hand | `hand.webp` | 3,218 | 原手和隐藏于袖口下的近端补片 |
| head | `head.webp` | 51,330 | 原头发、脸、耳朵与可见颈部 |

坐标原点在画布左上，x 向右、y 向下。SVG 正角为顺时针，以下点都使用 720 × 960 原画布单位：

| 关节 | x | y |
| --- | ---: | ---: |
| shoulder | 447 | 511 |
| elbow | 488 | 584 |
| wrist | 507 | 646 |
| neck | 369 | 468 |

SVG 层级必须保留累积旋转关系，且袖口在手的前面：

```text
body image
shoulder group
  upper-arm image
  elbow group
    wrist group
      hand image
    forearm image
head group
  head image
```

所有 image 在 `(0, 0)` 绘制，宽 720、高 960。上臂围绕 shoulder 旋转；elbow 组的旋转相对于 shoulder 组；wrist 相对于 elbow 组。头部独立围绕 neck 旋转。不要把五张整画布图片分别缩放到局部关节大小。

## 实际验证的动作

`rig.json` 中提供 2,600 ms 的参考时间线：从零姿态抬到 shoulder `-68°`、elbow 相对 `-64°`，手腕在 `-12°` 至 `+12°` 范围内摆动两次，随后所有角度归零。原型使用逐段平滑插值，body 始终不旋转、不平移，因此脚保持固定。头部招呼偏转最大 `-2°`；另外单独查看了头部 `-3°` 与 `+3°` 的待机反馈。

本素材子任务实际完成的验证范围是本地独立 SVG 原型，不能代替最终首页的可访问性、状态管理、会话逻辑、跨页面或移动端验收。这些集成结果由本轮站点验收文档另行记录。

- Chromium 中实拍待机、抬手、抬起、手腕外摆、手腕内摆、放下、回待机 7 个时间点，逐帧查看浅色和深色背景。最终袖肘没有原型首轮的突角，手腕与领口没有透底细缝；头发、脸和鞋完整。
- 连续完成两次实际时长的点击触发动作，检查真实 SVG 关节 transform 变化和恢复，未出现 pageerror。
- 起点与终点的人物 SVG 截图 SHA-256 相同，证明该原型动作复位后像素一致。
- 脚本对 201 个时间点计算变换后的图层包围盒，保守总范围为 `[116.93, 24.62, 634.67, 924.00]`，完整落在 720 × 960 画布内。
- 检查 body 原手区域的 alpha 为 0，避免保留第二只静止手；动作末帧所有关节角度严格为 0。

## 边界

这是保留原角色外观的二维分层骨架动画，不是带完整表面和骨骼的三维模型。只为已验证的正面招呼和小幅歪头补足最小遮挡区域，不能据此宣称支持任意姿态、转身、手指张合或背面动作。袖子接合区保留二维图层的绘制特征，不能将它描述成物理布料模拟。最终网站仍应保留原正面静态图，供资源失败和减少动态效果模式使用。
